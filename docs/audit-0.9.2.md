# مراجعة المختبرات · الإصدار 0.9.2

شملت المراجعة الحالات المتقدمة الخمسين والغرف الأساسية الثلاث عشرة. التحقق محلي؛ لم يُفحص أي موقع خارجي. النتائج تخص المدخلات ومسارات التنفيذ المختبرة، وليست ضماناً بخلو البرنامج من كل خطأ محتمل.

## ما تم التحقق منه

- حالات HTTP الفعلية ونوع المحتوى وطول الاستجابة وعدم التخزين المؤقت، مع فصل استجابة التطبيق عن تقييم التمرين.
- الطلب الصحيح، ومحاولة إظهار الخلل في الضعيفة، ونفس المحاولة في المُصلحة لكل حالة.
- عدم تغيير طلب الدفع أو المستند عند رفض العملية؛ محاولات الدخول المرفوضة لا تستهلك محاولة تحقق إضافية. تقدم الساعة المختبرية ليس تغييراً مالياً.
- الحقول الناقصة وغير المعروفة، الأنواع الخاطئة، JSON غير صالح أو مكرر الحقول، الأرقام غير المنتهية، Unicode غير صالح، وطرق HTTP غير المدعومة.
- تنفيذ المتصفح وعزل XSS، الحمولات السلبية والترميز، جلسات مستقلة، لغتان وعرض الهاتف.

## الأخطاء التي صُححت

1. كلمة مرور خاطئة في خدمة NoSQL أصبحت 401 مع invalid_credentials بدلاً من 200 مع authenticated:false. المدخل ذو النوع الخاطئ يبقى 422.
2. خطأ بناء استعلام SQL في الضعيفة أصبح 400 مع invalid_query؛ بحث مُعامل بشكل صحيح بلا نتائج يبقى 200 وقائمة فارغة.
3. مراجع التصدير والتنزيل مفصولة حسب نوع المورد، والموارد المفقودة تعيد 404. تم تصحيح بيانات CSV الخاصة بفاتورة alice.
4. الحقول المطلوبة تُفحص في الحالات الخمسين كلها؛ منع مدخلات Unicode غير الصالحة وJSON الملتبس قبل تنفيذ الحالة.
5. حمولات URL غير المعتادة لا تقطع معاينة XSS، وتوقيع webhook وCSRF غير ASCII لا يسقطان معالج الطلب.
6. أخطاء JavaScript في المعاينة تظهر للمستخدم ولا تمنح علامة إصلاح بناء على غياب alert الناتج عن خطأ تشغيل.
7. تم قفل اختيار النسخة والمدخلات خلال طلب معلّق، وإلغاء المعاينة القديمة عند تبديل النسخة، وإضافة اسم النسخة لنتيجة POST.
8. عرض حالة HTTP لا يخمّن إصدار البروتوكول. تم توضيح تفاصيل كل محاولة عند تجميع محاولات الريت ليميت.
9. الوجهة المحلية غير الموجودة لم تعد تُصنّف وجهة خارجية؛ السياسات المغلقة ما زالت ترفض الوجهات غير المسموحة.

## تفسير النتائج التي قد تلتبس

- **XSS:** استجابة 200 بعد ترميز النص أو عرضه عبر textContent صحيحة؛ لا يُطلب رفض كل نص يبدو كحمولة. المخزّن ينشئ تعليقاً بـ201 ومعاينته تُقرأ بـ200. التحقق من التنفيذ منفصل في المتصفح.
- **CORS:** قد يرجع الخادم 200 في النسختين؛ ما يحدد قراءة JavaScript هو ترويسات CORS وتطبيق المتصفح لها. اختبار المتصفح أثبت قراءة الضعيفة ومنع قراءة المُصلحة.
- **SQL والقالب:** تمرير المدخل كبيانات قد يعطي 200 بلا كشف بيانات أو تقييم تعبير. هذا ليس قبولاً للاستغلال.
- **إعادة الدفع:** إشعار صحيح مكرر يمكن إقراره بـ200 دون معاملة أو استحقاق جديد. القسيمة المستهلكة ليست نفس عقد إشعار المزود: تُرفض بـ409، والدفعة الجزئية 207.
- **الريت ليميت:** 401 تعني أن محاولة فاشلة وصلت للتحقق، وليست دخولاً ناجحاً. 429 تعني وجود حظر. عند إرسال مجموعة محاولات، تعرض operations حالة كل محاولة وattempts الأعداد.
- **قراءة المورد:** GET 200 يثبت نجاح القراءة فقط. نتيجة POST ونسخته تظهر منفصلة.

## الغرف الأساسية الثلاث عشرة

| الغرفة | ما تم التحقق منه |
|---|---|
| Enumeration | موجود 200 وغير موجود 404 في الضعيفة؛ استجابة موحدة 202 في المُصلحة |
| Rate limit | ثلاث محاولات 401 ثم 429؛ تغيير المصدر يعيد القبول في الضعيفة فقط |
| Email flood | 202 في النسختين مع أربع رسائل مقابل رسالة واحدة في الذاكرة |
| IDOR | قراءة مورد آخر 200 في الضعيفة و403 في المُصلحة |
| Edge/origin | المسار الخلفي 200 في الضعيفة و403 في المُصلحة؛ لا اختبار Cloudflare فعلي |
| Reflected XSS | إدراج خام مقابل ترميز HTML، مع إثبات تنفيذ وعزل في المتصفح |
| DOM XSS | innerHTML مقابل textContent، مع مصدر متصفح دون q في طلب المعاينة |
| CSRF | تعديل عبر أصل ثان في الضعيفة؛ 403 في المُصلحة؛ الطلب الصحيح يغير الملاحظة |
| CORS | جلسة مطلوبة 401 دونها؛ 200 مع اختلاف قابلية القراءة في المتصفح |
| Redirect | قرار تحويل فقط؛ قبول وجهة خارجية مقابل رفضها بـ400 |
| SSRF | نقل مغلق: قراءة عينة داخلية في الضعيفة و403 في المُصلحة |
| API keys | إزالة سر الخادم التجريبي مع بقاء المفتاح العام |
| Exposed files | ملف إعداد تجريبي 200 في الضعيفة و404 في المُصلحة؛ العام 200 |

## الاختبارات القابلة للإعادة

اجتاز الإصدار 59 اختبار Python، بينها مصفوفة للحالات الخمسين وفحص لجميع الغرف الأساسية، بالإضافة إلى مجموعات المتصفح الثماني التالية. توجد 36 صيغة حمولة/مقارنة XSS جُرّبت في النسختين، أي 72 مشاهدة متصفح.

```bash
python -m unittest discover -s tests -q
```

شغّل الخادم على 8000، ثم في بيئة تطوير فيها Node وPlaywright وChromium:

```bash
node tests/academy.cjs
node tests/payloads.cjs
node tests/payment_status.cjs
node tests/grouped.cjs
node tests/bilingual.cjs
node tests/browser.cjs
node tests/audit_edges.cjs
node tests/progression.test.cjs
```

اختبارات Chromium أدوات تطوير؛ تشغيل المختبر نفسه على Termux لا يحتاجها. يمكن تحديد متصفح محلي عبر BB_BROWSER_PATH.

## حدود المراجعة

الدفع يستخدم إيصالات ومزوداً محلياً وأموالاً تجريبية؛ حالة رصيد الهدية ترتيب تزامن حتمي وليست اختبار قاعدة بيانات موزعة. XSS له 11 سياق تنفيذ وإضافة URL لفحص سياسة href فقط. SSRF والتحويل وNoSQL والقالب أنظمة محلية مقيدة. المراقبة الزمنية لغياب alert ليست برهاناً عاماً على غياب XSS؛ لا توجد هنا نتائج فحص لخدمات إنتاجية.

English: all 50 advanced cases and 13 foundation rooms were audited locally using explicit HTTP contracts, state assertions, malformed-input checks and real-browser suites. See the matrix above; 200 is intentionally retained for safe rendering, empty parameterized search results, idempotent notifications and CORS responses whose readability is enforced by the browser. This is bounded verification, not a guarantee for all possible inputs.
