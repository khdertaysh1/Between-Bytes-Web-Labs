# حماية التحديثات بالاختبارات والمراجعة

الإعداد المقترح يشغّل اختبارات الخادم والمتصفح على كل PR وعلى تحديث main. اسم الفحص النهائي هو `quality-gate`. ينجح فقط إذا نجحت اختبارات Python على 3.10 و3.13، ومجموعات المتصفح الثلاث، وفحص قدرة الاختبارات على كشف التراجع. الفحص المتجاوز أو الملغى لا يُحسب نجاحاً.

## ماذا تحمي الاختبارات؟

تراجع الاستخدام السليم ورفض العمليات غير المسموحة، وحفظ حالة الطلب عند الرفض، وحالات الدفع والصلاحيات والعداد، وتجارب المتصفح والواجهة العربية والإنكليزية والهاتف. تعتمد على اختبارات المشروع الحالية للحالات الـ72. يشغّل فحص إضافي نسخاً مؤقتة يكسر فيها حماية الدفع وملكية المستند وربط رمز CSRF بالجلسة، ويتأكد أن الاختبارات ترفض هذه الأخطاء فعلاً. لا تتغير ملفات التطبيق الأصلية في هذه التجربة.

التطبيق لا يحتاج Node ليعمل؛ حزم المتصفح للتطوير فقط. أدوات التشغيل والسجلات وتعليمات حماية الفرع موضحة في [دليل المساهمة](../CONTRIBUTING.md).

## ما الذي لا يكفي وحده؟

نجاح الاختبارات لا يثبت غياب كل الأخطاء. إضافة ملف workflow لا تمنع الرفع المباشر وحدها؛ يجب تفعيل حماية main من إعدادات GitHub واختيار quality-gate كفحص إلزامي. إضافة GitHub المتصلة لا تملك صلاحية إدارة الحماية، لذلك ملف إعدادها جاهز للمالك في `.github/branch-protection.json`، ولا يجوز وصفها بأنها مفعّلة قبل تفعيلها فعلياً.

التعليمات الحالية للمهام الأسبوعية أصبحت: فرع مستقل وPR، دون رفع إلى main أو دمج تلقائي أو تجاوز الحماية. القرار النهائي للمستخدم. لا ينبغي حذف اختبار أو إضعافه لإخفاء فشل؛ أي تعديل للاختبارات أو CI يشرح صراحة في PR.

إعداد الحماية الجاهز يفرض PR والفحوص، مع صفر موافقات رسمية لتجنب تعطيل مستودع يملكه شخص واحد؛ GitHub لا يسمح للكاتب بالموافقة على PR كتبه بنفسه. المراجعة والدمج اليدويان سياسة التشغيل. وجود مراجع مستقل يسمح بفرض موافقة واحدة ومراجعة مالك الكود لحماية أقوى. ملف CODEOWNERS وحده لا يفرض مراجعة.

تغيير النموذج لا يبدّل هذه الفحوص المكتوبة. لكن فحوص المستودع وتعليمات المهمة لا تضمن استمرار الوصول للحساب أو المهام المجدولة بعد تغيير الاشتراك، ولا تمنع شخصاً يملك صلاحيات المالك من تعديل الحماية نفسها.

يرفض مشغّل Python الاختبارات المتجاوزة أو المعلمة كفشل متوقع، ولا يسمح بانخفاض عدد الاختبارات عن خط الأساس. ويتطلب مشغّل المتصفح إكمال المجموعة وظهور رسالة نجاحها النهائية، حتى لا يُحسب خروج مبكر بلا تنفيذ نجاحاً.
